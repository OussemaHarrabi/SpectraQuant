# `reports/paper/` — how this report is produced and how to regenerate it

This directory holds the research report source. It is **markdown**, hand-written prose, but every
headline number in it is copied from a committed artifact under `artifacts/sample-results/` and the
artifact path is stated next to the number. No headline number is retyped from a run log, a console
or memory.

## Files

| file | what it is | regenerated by |
|---|---|---|
| `paper.md` | the research report (all sections required by the Milestone-10 spec) | hand-written; not generated |
| `README.md` | this file | hand-written |

The report's numbers are **not** generated (the prose cannot be), so they are kept honest by two
mechanisms:

1. Every headline number is quoted verbatim from the artifact it cites; a spot-check list is kept in
   the report and re-checked by the claim-audit stream.
2. The quantitative tables and the figure the report leans on **are** generated, and a test fails if
   they drift.

## Tables and figures (generated — never edited by hand)

`reports/tables/` and `reports/figures/` are produced solely by:

```
uv run python scripts/reproduce/generate_release_artifacts.py
```

That script reads only the committed artifacts (no network, no RNG, no timestamps) and writes:

| report table / figure | artifact it is generated from |
|---|---|
| `reports/tables/proxy-ranking.md` | `artifacts/sample-results/proxy-validation/proxy-validation.json` |
| `reports/tables/proxy-fixture.md` | `artifacts/sample-results/proxy-fixture/proxy-fixture.json` |
| `reports/tables/allocator-frontier.md` | `artifacts/sample-results/allocation-frontier/frontier.json` |
| `reports/tables/regularizer-arms.md` | `artifacts/sample-results/regularizer/sweep.json` |
| `reports/tables/class4cpu-bytes.md` | `artifacts/sample-results/class4cpu/class4cpu.json` |
| `reports/tables/class4cpu-latency.md` | `artifacts/sample-results/class4cpu/class4cpu.json` |
| `reports/figures/pareto-damage-vs-bytes.svg` | `artifacts/sample-results/allocation-frontier/frontier.json` |

To regenerate into a scratch directory instead of overwriting the committed files:

```
uv run python scripts/reproduce/generate_release_artifacts.py --out /tmp/release-check
```

`tests/unit/test_release_artifacts.py` regenerates every file into a temporary directory and fails if
it differs from the committed one, so the committed tables and figure cannot drift from the
artifacts. To regenerate the artifacts themselves, see `reports/REPRODUCIBILITY.md`.

## How to read the numbers

* Every number carries a measurement class and a substrate label (`AGENTS.md` §5, §2b). Classes are
  never mixed inside a claim: class 2 is fake-quantization quality, class 3 is measured packed-storage
  bytes, class 4-CPU is a real CPU low-bit kernel executing a SpectraQuant container. A number that
  has not been measured is written **NOT RUN** and never estimated.
* `LOCAL-FIXTURE` results are Tier-0 fixtures, not language models; they are labelled as such and are
  never presented as confirmatory.
